# ERC-7802

**Yıl:** 2024
**Durum:** Draft
**Kategori:** Crosschain Mint/Burn Interface

## Özet
ERC-7802, token'ların köprüler tarafından standart biçimde `crosschainMint` ve `crosschainBurn` çağrılarıyla yönetilebilmesi için minimal bir arayüz tanımlar. Amaç, bridge-spesifik mint/burn entegrasyonları yerine ortak bir token tarafı arayüzü oluşturmaktır.

## Neden Önemli
ERC-20 dünyasında crosschain token hareketi büyüdükçe, token ile bridge arasındaki arayüz parçalanması ciddi bir sorun haline geldi. ERC-7802 bu problemi, token kontratına bridge-agnostic ve minimal bir mint/burn yüzeyi ekleyerek çözmeye çalışır. Bu yüzden token standardizasyonunun multi-chain çağındaki önemli adaylarından biridir.

## Temel Bileşenler
- `crosschainMint(account, amount)` — köprü kaynaklı mint girişi
- `crosschainBurn(account, amount)` — köprü kaynaklı burn girişi
- `CrosschainMint` / `CrosschainBurn` event'leri
- ERC-165 interface detection

## Tarihsel Bağlam
ERC-7802, ERC-20'nin L1 odaklı ilk yıllarından farklı bir problem uzayına aittir: aynı varlığın birden fazla zincirde temsil edilmesi. İlk token standardı tek zincirli taşınabilirlik sağladı; daha sonra crosschain kullanım yaygınlaşınca token-bridge arayüzünün de standartlaşması gerekmeye başladı.

Bu yüzden ERC-7802, token tarihindeki “bridge agnostic crosschain compatibility” aşamasını temsil eder.

## Sınırlamalar
- Hâlen taslaktır ve bridge ekosisteminin tamamında ortak norm haline gelmemiştir.
- Güvenlik tamamen yetkilendirilmiş bridge kontratına ve access control tasarımına bağlıdır.
- Wrapped native token senaryolarında yanlış kullanım ciddi collateralization riskleri yaratabilir.

## Bağlantılı EIP'ler
- [[ERC-20]] — temel fungible token standardı
- [[ERC-6864]] — sonradan yeni arayüz sınıfları eklemeye dönük evrim hattı

## Teknik Notlar
ERC-7802'nin önemli tasarım tercihi, crosschain mantığını token içinde detaylandırmamak; yalnızca gerekli kapıları standartlaştırmaktır. Böylece token kontratı bridge mantığıyla şişmez, ama köprüler yine ortak bir mint/burn yüzeyi üzerinden konuşabilir.

Bu minimalizm, standardın en güçlü tarafıdır. Ama aynı zamanda access control, limit ve fee politikalarının token implementasyonuna veya bridge tarafına bırakılması anlamına gelir; yani standart ortak bir kapı sunar, tam davranışı değil.
